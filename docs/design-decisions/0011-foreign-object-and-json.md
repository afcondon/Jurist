# 0011. `Foreign.Object` is an ordered object, and JSON is the backend's own

- Status: Proposed
- Date: 2026-11-19
- Extends: [0001](0001-runtime-representation.md) (one more runtime type) and
  [0002](0002-ffi-shim-doctrine.md) (four more core shims).
- Cross-backend: Gnomon supplies the same four shims
  (`backend-go/foreign/`); Pythia does not yet.

## Context

Glassbox (`purescript-glassbox`) is a state machine as a data artifact: a JSON
file, a pure runtime, and a claim that any runtime answers the same events
the same way. Its core has no foreign imports of its own. Compiled through
`purejl` in November 2026 it lacked exactly four foreign modules, all from
the registry: `Foreign.Object`, `Foreign.Object.ST`, `Data.Argonaut.Core`
and `Data.Argonaut.Parser`. These are standard-library surface, so by the
family rule they belong in the backend, never in the program that found the
gap.

On JavaScript these four are thin: an `Object` *is* a JS object,
`stringify` is `JSON.stringify`, and the parser is `JSON.parse`. Julia has
none of the three. Its `Dict` has no order, and Julia's standard library
has no JSON.

Order is the part that cannot be waved away. A JS object enumerates its
keys in a defined order, and `Foreign.Object.keys`, `values`,
`toUnfoldable`, `fold`, and the key order of `JSON.stringify` all show it.
The printed JSON is what crosses between runtimes, so a backend that
prints the same object with its keys in another order has produced a
different artifact. Gnomon found this first (2026-08-25): Go's
`encoding/json` sorts keys, and that was its one divergence on Glassbox.

## Decision

1. **A fifth runtime type, `PSObject`**, in `purejl_runtime.jl`: a vector of
   keys in first-insertion order beside a `Dict{String,Any}`. It is what a
   `Foreign.Object a` and a JSON object are. It enumerates its keys as
   JavaScript does: keys that are canonical array indices (`"0"`, `"7"`,
   `"42"`; an integer below 2³² − 1 with no leading zero) first, ascending
   numerically, then every other key in the order it was first inserted.
   Assigning to an existing key keeps its place.
2. **A `Json` value is the native value**, as on JS: `nothing`, `Bool`,
   `Float64`, `String`, a `Vector`, a `PSObject`. `fromNumber` and its
   siblings are the identity.
3. **`stringify` and `stringifyWithIndent` reproduce `JSON.stringify`**: JS
   number formatting through the runtime's `_js_number_string`, `-0` printed
   as `0`, non-finite numbers as `null`, the short string escapes and
   `\u00xx` for the other control characters and nothing else, an indent
   clamped to ten spaces, `[]` and `{}` kept closed.
4. **The parser is a strict RFC 8259 parser written in the shim.** It accepts
   and rejects what `JSON.parse` does. A repeated key keeps its first place
   and its last value.
5. **Both lanes use it.** The shims are `purejl`'s, and `backend-jl` consumes
   them unmodified ([0009](0009-two-implementations.md)).

The corpus modules `Test.ForeignObjects` and `Test.Json` hold all of this to
the JS backend line for line.

## What does not match JavaScript, deliberately

- **A record coerced to an `Object` has no source order.**
  `Foreign.Object.fromHomogeneous` is `unsafeCoerce` on a record. A record
  here is a `Dict{String,Any}` ([0001](0001-runtime-representation.md)),
  which has no field order to recover, so the shims take such a value's keys
  **sorted**. JS would give the order the fields were written in. The result
  is deterministic and it is not the JS order. Closing this means making
  records ordered too, which is a change to 0001 with a cost on every record
  access; it is not taken here. Nothing in the corpus can reach it without
  `unsafeCoerce`, so it has no ledger entry, and that absence is itself a
  thing this record states.
- **`k in m` on JS also sees inherited properties**, so
  `Foreign.Object.member "toString" empty` is `true` on JS. Here it is
  `false`. This is a JS accident and is not reproduced.
- **A fold that may stop early** (`_foldSCObject`) marks "stop" with `null`
  on JS. Unit and a JSON `null` are both `nothing` here, so a private
  sentinel marks it. A fold whose accumulator is legitimately `nothing` runs
  to the end, where on JS one whose accumulator is `null` stops at once.
- **Parse error messages are this parser's own.** V8 and JavaScriptCore do
  not agree with each other, so nothing portable can read them. The corpus
  tests that a bad document is rejected and never prints why.
- **A lone surrogate in a `\u` escape becomes U+FFFD.** Julia has no `Char`
  for it. This is the `ASTRAL` cause again.

## Consequences

- Glassbox's core runs on Julia unmodified. Its conformance vectors,
  generated by the Julia runtime, are byte-identical to the committed ones
  that Node generated (seven machines, checked 2026-11-19).
- `argonaut-core`, `codec-argonaut` and `foreign-object` move from MISSING to
  provided in the portability index.
- The JSON printer and parser are code this repo now owns, about 250 lines
  of Julia held as Haskell strings. The corpus is what keeps them honest.
- The shared corpus gains two modules that need these shims. Gnomon has
  them, with a known key-order divergence. **Pythia does not, and fails
  both modules until it does.** On Python an object can be a plain `dict`
  (insertion-ordered since 3.7) and the printer `json.dumps`, except for the
  array-index ordering and JS number formatting, which need the same care
  as here.

## Alternatives considered

- **Use `JSON.jl` or `JSON3.jl`.** Rejected: the backend's runtime has no
  package dependencies, and a compiled program should not need a Julia
  environment to print a value. Neither package formats numbers as JS does.
- **`Dict` for objects, and canonical (sorted) JSON everywhere.** Rejected as
  the backend's answer: it makes `Foreign.Object.keys` wrong for every
  program in order to make one printer agree. A program that wants a
  canonical form can sort for itself, as `Glassbox.Canonical` does.
- **`OrderedCollections.OrderedDict`.** Rejected for the same
  no-dependencies reason, and it would not give the array-index rule.
