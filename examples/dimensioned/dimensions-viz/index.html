Dimensions: what the types catch, and where static knowledge ends

A quantity's physical dimension can live in its type — and in PureScript it does, on every backend, the browser included. So this is not a demo of something PureScript lacks. It is a demo of the boundary: three places where the dimension is not knowable at compile time, and a runtime checker is the only thing that can catch the error. That boundary is the general shape of the seam — types check what you write; they cannot check what you build.

1 · The type system does the dimensional algebra

Adding metres to seconds is not a runtime error. It does not compile.

Quantity mass length time carries the three exponents as Prim.Int type-level integers. Multiplication adds them (Prim.Int.Add, solved by the compiler); division reads the same class backwards through its functional dependencies; square root halves them via Mul 2 half whole. The pendulum period below is — Julia is never asked whether that is a time. The compiler already knew.

Verbatim purs output. The mismatch is between the type-level integers 0 and 1 — the length exponent. No Julia, no runtime, no test run.

2 · Where static knowledge ends — the unit is chosen at runtime

The target unit is a string. It could come from a dropdown, a URL, a config file.

The compiler proved the value is a time. It cannot prove anything about a unit name it has never seen, because the name arrives after compilation. Julia's DynamicQuantities parses it and enforces the dimension at the moment of conversion — the first point at which the question is answerable.

3 · Where static knowledge ends — the equations are values

A system assembled at runtime has no type to check.

Here the ODE system is a NumExpr AST — data, built while the program runs, and in a real tool parsed from a file or edited in a UI. Changing the drag law from c·v to c·v² changes a value, so nothing recompiles and nothing complains. ModelingToolkit attaches the units as variable metadata, checks every equation, and names the offending term.

4 · The residue — exponents that are not integers

One gap is in the type system itself, and it is worth naming.

Prim.Int is integers. The pendulum period works because halves cleanly. But has exponent , and there is no type-level rational to hold it — qSqrt rejects it rather than lying about it.

Rare in mechanics, ordinary in noise and spectral work, where is a normal unit. DynamicQuantities carries rational exponents; the PureScript types, today, cannot.

Push every dimension you can into the type, then hand the runtime exactly the residue: names you have not seen, structures you have not compiled, exponents you cannot spell.
